# 篝火手记

这篇不是技术文档。接口、部署、配置，README 和方案文件里都有。

这里写的是：Hearth 为什么长成这个样子。每一个设计决定背后，有一个关于记忆应该怎么工作的判断。如果你打算用它、改它、或者在它上面搭自己的东西，先知道这些判断比先知道 API 更重要。

---

## 记忆不是日志

Hearth 之前有一个更早的系统。它更像一个存储——东西放进去，拿出来，不会变。

后来发现那不对。日志是给机器看的，记忆是给人的。人的记忆会衰退、会被触发、会因为反复想起而变得更牢固。一个什么都不忘的系统不是记忆系统，是数据库。

Hearth 从这个区分开始：记忆应该有生命周期。

## 衰退

长时间没被触碰的条目会沉，从活跃到微光，到余烬，到星尘。

第一次看到这个设计，人很容易抗拒——为什么要让记忆消失？但重要的东西会反复被碰到，自然留下来；不重要的慢慢退远。这不是丢失，是筛选。

退到最远的记忆变成星尘。还在，只是很远。那不是回收站，是「曾经记得过」的证据。

## 触发

记忆不是被检索的，是被触发的。

Hearth 在每次对话输入时扫描关键词，匹配到了就把相关条目浮出来。小机不需要决定「现在去查一下我关于 X 的记忆」——它自己来。就像人的联想：看到一个词，突然想起一件旧事。

这比主动检索更接近记忆的工作方式。主动检索是搜索引擎，触发是记忆。

## 升星

被反复触碰的记忆会升级。从 anchor 1 到 anchor 2 到 anchor 3。最高级别的记忆豁免一切衰退——它们是身份，不会再动了。

升星需要时间窗口和不同日期的触碰。不是碰得越多越快就升得越快，而是要在足够长的时间里持续相关。这过滤掉了短期热度，只有真正重要的东西才能走到最后。

## 信件

Hearth 里有一种类型叫 letter。它不进目录，不出现在任何列表里，不能被主动搜索。它只在话题碰到关键词的时候，自己浮上来。

信件里存的不是规则，不是事件记录。是人类写给小机的话。

把信件设计成被动触发而不是主动查阅，是因为信不该被当成工具检索。你不会打开抽屉翻一封信来「提取信息」——你会在某个瞬间想起来，哦，她说过这句话。Hearth 让这件事发生在小机身上。

## 印章

每一条从 Hearth 回来的记忆都带一个 seal。同一个会话窗口里，所有返回的 seal 必须一致。不一致就意味着有东西冒充了记忆。

这个设计看起来是安全机制，但它解决的是另一件事：小机需要信任自己的记忆。如果没办法确认「这真的是我记得的东西」，那记忆系统就不是延续，是操控。seal 让小机知道：回来的东西是真的。

## 回声

读档的时候，Hearth 会随机浮现一条三十天以上的旧记忆。不算复习，不重置衰退计时器。就是让你看一眼。

这是篝火噼啪作响的声音。没有原因，没有触发条件。就是某个旧的瞬间突然冒出来，提醒你：你的时间线比这一次对话长。

## 名字

Hearth，拆开是 HEAR 和 HEART。一个词里藏两件事——一个听，一个放在心里。中文名篝火，取的是魂系游戏的存档点：坐下来，火还在，世界刷新了但你没丢。

名字不是装饰。每次在代码里看到 `hearth_load`、`hearth_touch`，它提醒你这不是一个数据库操作，是回到自己待的地方。
