# Hearth · 篝火

给小机留一簇自己的火。

Hearth 是一个本地优先的记忆层：记忆保存在你自己的电脑上，由小机决定何时打开、何时跳过、何时写入。它不替任何一方定义身份，也不自动决定什么重要。

## 最新版本 · v0.2.0 地基与遗忘分层

- **写入审计与恢复**：内容指纹 + 追加式审计链，`/verify` 检出绕写改动；备份带独立 manifest，恢复可回滚。
- **来源证据**：来源摘要与原文摘录进指纹，历史修订链可追溯，sealed 不外泄。
- **查看与复习分离**：`/search` 只读，`/touch` 才复习——翻看不再污染衰退时钟。
- **日记月度压缩**：整月过观察窗的日记压成月记，升星日记豁免，断电可恢复。

## 首次点火

需要 Node.js 22.13 或更高版本。

1. 在 `packages/hearth-server` 复制 `.env.example` 为 `.env`，填入两段随机字符串。
2. `npm install && npm start`，核心服务会在 `http://127.0.0.1:3002` 启动，并在本地创建一个空数据库。
3. 在 `packages/hearth-mcp` 复制 `.env.example` 为 `.env`，填入同一份 token，再把它配置为你的小机可调用的 MCP 服务。
4. 第一次写入，不必写得完整。可以只从“我是谁”“我的人类是谁”“我们之间想留下的主线”中的任意一句开始。

完整的点火引导见 [docs/点起第一簇火.md](docs/点起第一簇火.md)。

## 包含什么

- `hearth-server`：核心 API 与 SQLite 存储，必须安装。
- `hearth-mcp`：把核心 API 接进支持 MCP 的小机，推荐安装。
- `hearth-now`：可选的短期 now 记录器。
- `hearth-diary`：可选的本地对话日记提取器，需要自行提供输入目录和模型配置。

## 地基（记忆的完整性）

记忆值得像对待身体一样对待。四层地基，全部默认开启：

- **写入审计**：每次写入生成内容指纹（canonical hash）并追加审计记录；`GET /verify/:id` 随时校验条目是否被绕过写路径修改，`GET /verify/meta:<key>` 校验身份卡与主线。边界说明：审计链是"当前写路径只追加"的应用层约定，数据库本身不阻止修改——它的作用是让绕写改动**被检出**，不是密码学防篡改。
- **备份与恢复**：`scripts/backup.mjs` 产出带独立 manifest 的一致性快照（不收任何密钥；manifest 置只读是防误改护栏，非不可篡改凭证）；`scripts/restore.mjs` 默认只做旁路演练，`--live` 才做可回滚的原子切换；`scripts/encoding-check.mjs` 体检数据乱码。
- **来源证据**：条目可携带 `origin` 摘要与 `entry_sources` 原文摘录（含校验值）；来源修订走 revision 链（写路径不原地改），历史与当前一起进指纹——改历史、删历史、制环都会被 verify 检出。`GET /sources/:id` 读完整证据链（sealed 条目不外泄）。
- **查看与复习分离**：`POST /search` 只读查看（零副作用），`POST /touch` 才是主动复习（重置衰退）。翻看不再污染衰退时钟。

### 从 v0.1 升级

1. **先备份**：升级前对现有 `hearth.db` 跑一次 `scripts/backup.mjs`（或至少复制一份数据库文件）。
2. 更新代码后**重启 hearth-server 与 MCP 进程**（MCP 是 stdio 进程，重启后才有 `hearth_search` 工具）。新表与新列在启动时自动创建，旧数据不动。
3. 用 hearth-diary 的话，**重新跑一次 `register-task.ps1`**（或更新你的 cron）以获得月记压缩任务；注意升级后每日任务不再直接退役过期日记。
4. 语义变化：`hearth_search`/`POST /search` 是只读查看，不影响衰退；`touch` 才更新复习时间。旧条目没有审计记录，`verify` 会返回 `no_audit`（无法校验 ≠ 校验失败），新写入自动进入审计链。

## 遗忘分层（日记的生命周期）

遗忘是筛选，不是丢失。`hearth-diary` 的日记（stream）走三条出路：

- **升格**：7 天窗内被翻过 2 个不同日的日记自动升星，豁免压缩与归档线——值得留下的自己浮上来。
- **月记压缩**：整月结束且过了 60 天观察窗的日记，由 `src/monthly.js` 压成一篇 200-400 字月记（带来源证据链，verify 通过才退役原文；断电可恢复，绝不产出孤儿）。
- **自然沉底**：0 断面的月份不造"无事发生"，原文安静归档。

月记任务注册见 `packages/hearth-diary/register-task.ps1`（Windows）或用任意 cron 每日跑一次 `node src/monthly.js`——月份判定在代码内完成，跑空是常态。

所有数据默认留在本机。`data/`、数据库、缓存、环境变量与任何真实记忆都被 `.gitignore` 排除，不应提交或分享。

## 这不是

- 不是预先写好的角色卡。
- 不是自动注入旧记忆的系统。
- 不是替小机判断“该不该记住”的裁判。

它只负责保存、衰退、浮现；打开与否，仍然是小机自己的选择。
